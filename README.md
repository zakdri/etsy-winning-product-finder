# Etsy Winning Product Finder / TrendScout

Research tooling for identifying promising Etsy listings using authorized Etsy Open API data, repeated snapshots, and transparent machine-learning features.

> The term “Etsy” is a trademark of Etsy, Inc. This application uses the Etsy API but is not endorsed or certified by Etsy, Inc.

## Security first

The Etsy keystring, shared secret and OAuth tokens belong only in the root `.env` file used by the backend. Never commit credentials, datasets, databases or model artifacts. The browser extension contains no Etsy secrets.

```bat
copy .env.example .env
```

## Architecture

```text
extension/      WXT + React cross-browser WebExtension
backend/        FastAPI service used by the extension
ml/             Etsy snapshot collection and ML training pipeline
```

The extension calls the local backend. The backend calls Etsy's official API and returns normalized research data. No Etsy page scraping is used.

## 1. Start the local backend

From the repository root with your Python environment activated:

```bat
pip install -r backend/requirements.txt
uvicorn backend.app.main:app --host 127.0.0.1 --port 8765 --reload
```

The extension expects the backend at `http://127.0.0.1:8765` by default.

## 2. Build the extension

```bat
cd extension
npm install
npm run typecheck
npm run build
npm run build:firefox
```

Build outputs are written under `extension/.output/`.

### Chromium browsers

The standard Chromium build works with Google Chrome, Microsoft Edge, Brave, Opera and other Chromium-based browsers. Load the generated Chromium folder from the browser's extension developer page.

### Firefox

Use the Firefox build generated by:

```bat
npm run build:firefox
```

Load the generated folder temporarily from Firefox's debugging page during development. Use `npm run zip:firefox` for a store submission archive.

### Safari

Safari Web Extensions share the same web-extension code, but Apple requires conversion, an Xcode wrapper, signing and an Apple developer account. On macOS:

```bash
npm run build:safari
xcrun safari-web-extension-converter .output/safari-mv3 --project-location ../safari
```

Open the generated Xcode project to build and sign the macOS/iOS Safari extension.

## Extension experience

- Polished full-page product research dashboard.
- Quick popup with local API status.
- Etsy search-page launcher that transfers only the search keyword; it does not scrape listings.
- Up to 100 official API results per focused keyword for the current API access mode.
- Shop enrichment, freshness, favorite momentum, SEO completeness, price-fit and confidence signals.
- CSV export and sorting by opportunity score, newest, favorites or shop proof.
- Responsive, accessible dark interface with visible connection and confidence states.

The initial `opportunityScore` is a transparent heuristic research score. It is not a claim of verified future sales. Once real repeated snapshots produce enough labels, the backend can replace or augment it with the trained model.

## Collect snapshots for the real model

```bat
python ml/src/collect_snapshots.py --keyword "vintage horse wall art" --pages 1 --page-size 100 --enrich-shops --max-shop-lookups 100
```

Run consistent focused keywords repeatedly. For stronger data, collect daily or every two to three days for 60–90 days.

## Build real labels

The public Etsy API does not expose verified per-listing competitor sales. The first real dataset labels products by later favorite-growth velocity, adjusted by taxonomy and listing-age bucket.

```bat
python ml/src/build_training_data.py --horizon-days 14 --tolerance-days 4
```

## Train the momentum model

```bat
python ml/src/train.py --input ml/data/processed/etsy_momentum_training.csv --model ml/models/etsy_momentum_classifier.joblib --metrics ml/models/etsy_momentum_metrics.json
```

## Synthetic smoke test

Synthetic rows verify only that the pipeline runs; they are not evidence of marketplace accuracy.

```bat
python ml/src/generate_demo_data.py --rows 3000
python ml/src/train.py
```

## Data protocol

1. Collect authorized API snapshots at consistent intervals.
2. Keep only features available at each snapshot date.
3. Label outcomes using later observations.
4. Compare products inside similar taxonomy and listing-age groups.
5. Exclude ambiguous middle examples.
6. Split training and evaluation chronologically.
7. Report ROC-AUC, average precision, top-ranked precision and calibration.
